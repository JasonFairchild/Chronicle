## Decisions

- **One change type from editor to store.** `EditorChange` (`DocumentEditor.vue`) and `DraftChange` (`draftsStore.ts`) became the same shape once the editor stopped emitting anchor ids and the title. One `DraftChange` in `types/draft.ts`, since it crosses a component, a composable and a store (CLAUDE.md, "Types live by who uses them") and is the working stage in ARCHITECTURE.md's table. The editor's comment on why its signals are required moves with it.
- **`baseContent` takes a string only.** `EntryDocument` was accepted for AnchorMenu's specs alone (TESTING.md: never loosen a source type for a test).
- **While composing, the page's `<h1>` names the task.** "Revise entry" and "Create related entry", the buttons that open them, as New entry's page already does. Reading keeps the entry's heading. This removes the title shown twice in both modes: the Title field is a revision's only title, and the related-entry page's left column is the only place the parent's is shown.
  - Left column: This entry, the parent's heading (its title, or its dateline muted when untitled, as the reading header does), its meta line, its editor, then the instructions, with the right column's "Marking a passage is optional" folded in. Right column: The related entry, then EntryComposer. Each column's label, heading and editor then line up.
  - The view passes the parent's heading and meta line in as props, from the computeds it already has. `session.parentTitle` goes: it was the title when the session began and was never refreshed on returning to the tab, so it could disagree with the meta line beside it.
  - The ids become `useId()`, as EntryComposer's are.
- **One anchor index per document, before Track B reviews the editor.** CHRONICLE_PLAN.md decided it as §5.4's first step; nothing waits on §5.4, and Track B unit 2 should review the final shape. Today a caret move in anchor mode walks the document about six times (the decorations, AnchorMenu's `caretAnchor` and `shouldShow`, each through `anchorSpans` and `anchorPieces`).
  - `anchorIndex(doc)` in its own module, `editor/anchorIndex.ts`: each anchor by id, in document order of its first piece (`ownAnchorAt` relies on it where two touch), with its outer span, kind, and passage and wording pieces, each piece keeping its mark instance for `removeMark`. An id that isn't a non-empty string is skipped, `anchorSpans`'s rule (`anchorPieces` turned it into `"null"`).
  - Memoized in a `WeakMap` keyed by the document: ProseMirror documents are immutable, so it's one walk per new document and none per caret move.
  - It replaces `anchorSpans`, `anchorPieces` and `piecesOf` in the commands, the decorations and the guard. The guard's outcome check, a slice per sealed anchor, is unchanged.
  - `AnchorRange` leaves the domain, and `anchorRangeOverlapping` is inlined into `markAnchor`, its one caller. Its touching-edge case gets an editor-level test, which nothing has today.
  - Left alone: `markTyped` (it reads only beside the typed range), `markFrames`'s `visibleIn`, the domain's JSON walks, and DocumentEditor's `collectAnchors` for the parked raised-wording mode.
  - Rejected, carried over from CHRONICLE_PLAN.md: a `DecorationSet` of sealed anchors mapped through each change, which sees text move but not marks added. Further, only if a profile shows it: an index per top-level block.
- **Orphaned anchors go, ahead of CHRONICLE_PLAN.md item 3.** The lock keeps every sealed anchor in its parent's document, and a related entry is sealed after its anchor revision in one `createMany`, so no version viewed lacks an anchor a visible related entry names. The orphan path and the quote saved for it are dead.
  - `AnchorRef` goes: a related entry stores `anchor_ids: string[]`. Connections folded may need each to name the entry whose document it marks, but nothing old is kept compatible, so item 3 settles that shape when it needs one.
  - `resolveAnchors` and `placedAnchors` go. The fold, the one reader left, reads the viewed version's anchors once and looks each id up, skipping any it lacks. `ResolvedAnchor` and `AnchorStatus` go; `DocumentAnchor` moves to `types/entry.ts`, since it now crosses from the domain to the page, and its `quote` and `insertion` become `passage` and `wording`, the docs' own terms (`quote` echoed the retired stored quote).

The interfaces and the composition root stay: they are what makes SQLite a swap. Spiked: all three store specs pass, 54 tests, with the changes below. `InMemoryMediaRepository` goes in the same commit, so the docs saying every repository has an in-memory twin change once: no node spec stores media, and media code needs a browser anyway (blobs, object URLs, `<img>`).

Its first line imports `fake-indexeddb/auto`: Dexie reads the global `indexedDB` when its module loads, so the import must come before `realRepositories`, and inside the file the order can't be got wrong. The lost-write race test's delayed `getById` goes: real IndexedDB already yields, and without the delay the test still fails when `write`'s replaced-session check is removed.

The clone ran at `put`, after the stored-write check's read, so it never covered that wait, and IndexedDB clones at `put` anyway.

Each runs once, in the browser, against Dexie; not in node too, which would prove fake-indexeddb rather than the adapter. - **Specs run on the composition root's own repositories, cleared between tests; its setters go.** The app never calls the setters: they are source's one entry point for tests (TESTING.md, "Test the code the app runs"), and `realRepositories.sharedDatabase()` copies the root's one-connection decision, with a paragraph on why the copy must match. With them gone, specs run the wiring the app runs. Spiked in `spikes/shared-database/`: every suite passes, on shuffled orders and with Cypress in parallel, and the change is net −12 lines.
  - Parallel stays. Vitest's Playwright provider gives each parallel worker its own browser context, which shares no storage with another, and a worker runs its files one after another (`BrowserPool` in Vitest 4.1). Node gives each spec file its own fake-indexeddb. Cypress runs one spec at a time and never clears IndexedDB itself; a second Cypress process can't take the fixed port, so gets another origin and its own storage. So one `chronicle` database per runner slot, cleared between tests, is isolated wherever tests run at once. Measured 2026-11-10: Vitest browser 20s in parallel and 37s serial, Cypress 80s (41s in specs).
  - **The cost is isolation by construction.** Today a late write can't reach another test: disposal deletes the database, and Dexie's `delete()` closes the connection for good, so the write fails and `write` swallows it. Under a clear, it lands in the next test. Waiting on store actions alone doesn't stop it, even with every Pinia tracked: in the spike, typing with its flush timer pending (`markDirty`'s timer calls the inner `flush`, not the action) and another tab's claim (`beginDraft` returns before its write) both reached the next test.
  - So teardown drains every writer before the clear, looped until a pass starts nothing: each drafts store's `flushAll()`, which cancels flush timers; every store action; and every call on the root's four repositories, through a pass-through wrapper the test module puts on them. Then one task, not a microtask: an unmounted view's own async function (EntryDetailView's `loadEntry`) can start the next action once the one it awaited settles. The drain gives up after 5 s, failing the test with what still runs, and forgets it, so later tests don't wait on it.
  - Anything after the drain fails loudly. An action on an ended test's Pinia throws, naming itself; a repository call between a test's drain and the next test's clear fails a hook. The one silent path is code outside the stores and `useMedia` calling a repository, which ESLint `no-restricted-imports` on `@/repositories` outside `src/stores/`, `src/composables/useMedia.ts` and `src/testing/` rules out. What remains: a hang that later resolves can write into the next test, after the hung test has already failed by name.
  - The clear runs before each test as well as after, so the start state doesn't depend on how the last test, file or aborted run ended. It is a backstop only: IndexedDB finishes a write whose transaction already exists before the clear, but one on a connection not yet open, or issued in the tick Dexie defers its explicit transaction to, goes after it (spiked in Chromium and fake-indexeddb alike). Every table in one transaction, through a test helper's own connection, so the root exports nothing for it, and Dexie's own table list, so a new table is covered. In the browser, the `media` OPFS directory goes too; the adapter looks it up afresh on every call. In node, the IndexedDB half runs only if the database exists, so domain specs pay nothing.
  - Every Pinia a spec makes is tracked: one `createTestPinia()`, shared by `renderComponent`, `cy.mount` and the 12 specs that call `setActivePinia` themselves, installed into a throwaway app as it's made. Pinia applies a plugin only once installed, and a Pinia a spec only activates never is, so today's `trackStoreActions` tracks none of them, node's included.
  - A test that holds a call in flight releases it before it ends: EntryComposer's "while a save is in flight" pair rejects its held `seal` last. Held forever, it hung every drain after it.
  - **A stub now outlives its test**, since the instance does: EntryDetailView's failing-load test leaves `listDescendants` rejecting for the next. `restoreMocks: true` in `vitest.config.ts`; Cypress restores its own. draftsStore.test's `vi.restoreAllMocks()` goes.
  - The adapter specs keep their own instance, over one `new ChronicleDatabase()` per file, not the root's: once SQLite is wired in, a Dexie spec must still prove Dexie. The global clear empties it like any other connection to `chronicle`.
  - Test-only constructor parameters go: `ChronicleDatabase`'s name (it already defaults to `chronicle`; only the root passes it) and `OpfsMediaRepository`'s directory. The persistence tests write through one instance, close it, and read through another, on the defaults; their unique names and their own deletes go.
  - TESTING.md's "Fresh instance per test, not a shared singleton that gets cleared" was written for the in-memory repositories; it becomes fresh Pinia and router per test, with storage the app's own, cleared before and after. It gains: "A test that holds a call in flight releases it before it ends: teardown waits for it, and fails the test after 5 s."
  - Rejected: serial Vitest browser files, unneeded given per-worker contexts. A database name read from a test-set global before import, which keeps a seam and hides it. `vi.mock('@/repositories')`, which Cypress can't share. Keeping the setters with one exported `repositoriesOver(database)`, the fallback had the spike failed. Closing and reopening the root's connection as a fence: the same Dexie object reopens, so an old store's write goes through again.
